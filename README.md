# ПРОСТОВПН WEB PROXY — 0.11

Интерфейс установки адаптирован из [andrchq/mt_proxy 2.1.0](https://github.com/andrchq/mt_proxy/blob/main/mtproxy.sh):
рамки, этапы, последние 10 строк журнала и дашборд с командами.
Движок остаётся WEB Proxy с SelfSteal; ссылки подключения — `t.me/webproxy`.

Новый порядок: проверка зависимостей → проверка сети → домен и режим → @MTProxybot/AD_TAG →
необязательный Telegram-бот → DNS → конфигурация → сборка → запуск/TLS → проверка.
Порт WEB Proxy фиксирован: 443. Секрет из регистрации сохраняется в backend и WEB-релее.
Bot Token вводится скрыто, не сохраняется; пустой ввод пропускает отправку ссылки.

Перед запуском установки и каждым этапом терминал очищается. В шапке
показываются предыдущие ответы и результаты этапов. Bot Token в сводку не попадает.
Цвета: шапка — синий, заголовок этапа — голубой, лоадер — пурпурный;
✓ зелёный — успешно, ✗ красный — ошибка, ! жёлтый — предупреждение,
− серый — пропущено. Загрузчик сначала проверяет свои зависимости, затем
основной установщик проверяет все системные пакеты, Docker и Compose;
apt устанавливает только недостающие пакеты.

Меню теперь выбирается номером и Enter. Команды: `sudo zlp status`,
`start`, `stop`, `restart`, `logs`, `links`, `stats`, `mode [https|https-lanes]`,
`ad-tag [HEX|off]`, `secret`, `qr`, `tls-domain`, `backup`, `update`, `version`, `uninstall`.
`tls-domain` открывает управление сайтом и сертификатами SelfSteal.
`backup` сохраняет настройки, Compose и сайт; TLS volumes резервируются отдельно.
`uninstall`: YES подтверждает удаление контейнеров; затем Enter сохраняет данные,
DELETE удаляет настройки, сайт и Compose volumes в штатных каталогах.
Установщик и резервные копии сохраняются. Удаление прежней systemd-установки отключено.
Снимок ссылки после установки: `/opt/prostoweb/info.txt`, права 600.

Установка на Ubuntu 24.04 / Debian 12–13, x86_64, systemd:

```bash
curl -fsSL https://raw.githubusercontent.com/Zapupinskiy/prstaproxy/main/install.sh -o /tmp/zlp-install.sh && sudo bash /tmp/zlp-install.sh
```

Перед установкой создайте A-запись домена на публичный IPv4 сервера, без CDN
и AAAA-записи. Порты 80 и 443 должны быть свободны и доступны из интернета,
включая firewall провайдера. Установщик сам ставит зависимости и Docker Compose.
Локальный порт 9443 тоже должен быть свободен.

```bash
sudo zlp                 # меню из любого каталога
sudo zlp обновить        # проект, контейнерные образы и глобальные команды
sudo zlp --status        # снимок дашборда
zlp --version
```

В root-сессии команда обновления: `zlp обновить`.

Главное меню содержит операции управления из списка выше и дополнительные
настройки WEB Proxy. Во всех меню сверху название в рамке и блок состояния.
Состояние считывается при открытии меню. Выбор выполняется номером пункта.
Режим iPhone — `https`; для остальных устройств — `https-lanes` при поддержке
клиентом. В настройках спонсора доступны просмотр, установка и отключение тега.
Спонсорский тег получают у @MTProxybot; его наличие не гарантирует
показ канала в клиенте.

Установка следует порядку выше. Длительные операции показывают последние
10 строк журнала. Ввод домена и выбор режима интерактивны.
Журнал: `/var/log/prostoweb-install.log`.

Три контейнера: Caddy SelfSteal, официальный MTProxy и telegramdesktop/tproxy-server.
Они используют общее сетевое пространство MTProxy, поскольку WEB-релей
разрешает только loopback-адреса listener/backend/admin. Наружу публикуются
только 80/443; административный API и backend не публикуются.
SelfSteal слушает HTTPS на 9443, опубликованном только на `127.0.0.1` сервера
(Reality target: `127.0.0.1:9443`, xver: 0). WEB Proxy обслуживается на 443.
Домен, Caddy, TLS-сертификаты, сайт и Compose-проект общие. Сайт отдаётся
WEB-релею через приватный HTTP listener Caddy на 18083; этот порт не публикуется.
Docker запускает контейнеры после перезагрузки. MTProxy ежедневно обновляет
конфигурацию Telegram и перезапускается для применения.

Блок состояния разделён на режим, общий статус, подключения/скорости и ссылки.
Статусы отдельных контейнеров и служб не перечисляются: показывается «ОК»
или «НЕ ОК», а при ошибке ниже перечисляются только проблемные службы.
Проверяются Docker, нужные контейнеры и их healthcheck, доступность метрик WEB-релея;
для прежней установки — только нужные ей службы systemd.
Подключения не равны уникальным людям. Скорости рассчитываются между снимками
при открытии меню; в первом снимке или при недоступных метриках отображается «—».
Единицы выбираются отдельно для приёма и отдачи: ниже 1 МБ/с — Кбит/с,
от 1 МБ/с — МБ/с, от 1 Гбит/с (125 МБ/с) — Гбит/с.
Используются десятичные единицы: 1 байт = 8 бит.
В подменю служб доступны запуск, остановка, перезапуск и журнал.

Данные сохраняются в `/opt/prostoweb/config`, сайт — `/opt/caddy/html`,
нативные Caddyfile, `.env` и журналы SelfSteal — в `/opt/caddy`.
Сертификаты — в прежних Docker volumes проекта; обновление не создаёт второй
сертификатный том. Замените сайт собственным или выберите шаблон командой
`sudo selfsteal template`: изменения сайта применяются без перезапуска релея.
Секреты хранятся с правами 600; каталог проекта на сервере
доступен root. При обновлении конфигурация сохраняется, перед заменой образов
создаётся резервная копия; неудачная проверка вызывает откат образов и Compose.
Операторское обновление не меняет автоматически закреплённый upstream commit:
новые версии backend должны проходить проверку и закрепляться в Dockerfile.

SelfSteal встроен на основе штатных функций скрипта
[DigneZzZ/remnawave-scripts](https://github.com/DigneZzZ/remnawave-scripts/blob/e18fae58f6f98727c682af023f2269fd434324a1/selfsteal.sh),
версия 2.11.1 (MIT). Сохранены установка/рандомизация шаблонов, резервные способы
скачивания, зеркала Docker, настройки Caddy и команды TLS. Исходник закреплён
в `vendor`, лицензия и сведения об адаптере сохранены рядом.

```bash
sudo selfsteal                # общее меню сайта и TLS
sudo selfsteal template       # штатный выбор шаблона
sudo selfsteal status         # службы и сертификат
sudo selfsteal renew-ssl
sudo selfsteal reissue-cert
sudo selfsteal edit
sudo selfsteal logs
sudo selfsteal up
sudo selfsteal down
sudo selfsteal restart
sudo selfsteal update         # то же обновление, что zlp обновить
```

`selfsteal install` открывает общую установку; `selfsteal up/down/restart`
управляет общим стеком, а не второй копией Caddy. `/opt/caddy/docker-compose.yml`
ссылается на общий Compose-файл; в нём явно закреплено имя `prostoweb` и
абсолютные пути, поэтому команды из обоих каталогов обращаются к одному проекту.
`selfsteal uninstall` после подтверждения удаляет контейнеры общего стека,
сохраняя данные и volumes для повторной установки.

Контейнерные версии 0.2/0.3 переносятся при обновлении/первом запуске новой панели:
сохраняются домен, секрет, сайт и TLS volume. Перед переносом создаётся резервная
копия, при ошибке восстанавливаются конфигурация прокси, Compose и файлы SelfSteal.
Отдельная существующая установка SelfSteal или Nginx автоматически не заменяется;
для её объединения необходим отдельный перенос. Встроенная установка использует Caddy.

Для серверов версии 0.1 (systemd/SelfSteal) первоначальное обновление панели:

```bash
sudo git clone https://github.com/Zapupinskiy/prstaproxy.git /opt/zlp-bootstrap && sudo bash /opt/zlp-bootstrap/prstaproxy.sh --install-menu
sudo zlp обновить
```

Существующие systemd/SelfSteal установки сохраняются: обновляются панель
и команды, службы управляются прежним способом. Автоматическая миграция
их конфигурации в контейнеры не выполняется. Новая установка требует свободных
80/443 и не перезаписывает обнаруженный прокси.

Локальная проверка:

```bash
bash -n prstaproxy.sh
bash -n lib/core.sh
bash -n lib/interface.sh
bash -n lib/ui.sh
bash -n lib/selfsteal.sh
bash -n install.sh
bash -n docker/mtproxy-entrypoint.sh
python3 -m unittest discover -s tests
```

Полная серверная проверка включает сборку образов (в Dockerfile релея запускаются
upstream Go-тесты), `/readyz`, валидный HTTPS и подключение Telegram-клиента.

В «Настройки → Секрет» доступны просмотр секрета, генерация нового, ввод собственного (32 hex или dd + 32 hex), ссылка и QR-код. Смена требует подтверждения и пересоздаёт контейнеры: старые ссылки перестают работать. Ввод собственного секрета поддерживается в контейнерной установке.

В дополнительных настройках доступны режим передачи, спонсорский канал, секрет, службы и SelfSteal/TLS. Просмотр текущего секрета выводит 32 hex символа без транспортного префикса dd; ссылка подключения сохраняет dd.

После смены режима проверяются готовность WEB-релея, слушающий порт MTProxy и HTTPS. Если перезапуск или проверка не удались, выводятся ошибка и последние записи журнала WEB-релея, восстанавливается прежняя конфигурация профилей и повторяется запуск с проверкой. При неудаче восстановления запуска выводится отдельная ошибка.
